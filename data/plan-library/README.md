# 진로계획 라이브러리 (plan-library)

우선순위 직업 100개의 **예시 진로설계**와, 여러 직업이 함께 쓰는 **보편 프로젝트**를 모아 두는 곳이다(2026-11-13 시작).
진로 설계하는 사람이 빈 화면에서 시작하지 않게 하려는 자료이고, 쌓일수록 서비스의 재산이 된다.

> 지금은 **초안**이다. Claude 가 직업정보·공식 자격 목록·일반 지식으로 썼고, 채용공고 분석 근거는 아직 없다.
> "공고 몇 %가 요구" 같은 숫자는 쓰지 않았다. `verify` 는 바뀌기 쉬운 사실(시험 과목·응시자격 등)이라 확인이 필요한 곳이다.
> 앱·DB 에는 아직 넣지 않았다(이 브랜치는 배포되지 않는다).

## 파일
| 파일 | 내용 |
|---|---|
| `taxonomy.json` | 분류 — 활동 유형 7가지(자격·학업·스킬·경험·산출물·채용 절차·네트워킹), 공통성 3단계(전 직무·계열·직무 특화), 계열, 계열별 묶음 |
| `common-projects.json` | 보편 프로젝트. id 는 `cp.<이름>` |
| `priority-jobs.json` | 우선순위 직업 100개 — 통칭, 계열, 세부 카테고리(tracks), 같은 계획을 함께 쓰는 직업(covers) |
| `job-groups.json` | 추천 직무 112개와 1차에 넣은 직업, 뺀 이유 |
| `plans/<jobCode>.json` | 직업별 예시 진로설계 |

## 직업 계획의 구조
- `projects`: 그 직업만의 프로젝트(id 는 `p.<이름>`). 보편 프로젝트와 같은 모양이다
- `common`: 세부 카테고리와 상관없이 하는 것 / `byTrack.<id>`: 그 카테고리에서 더 하는 것
- 항목 = `{ ref, step, major, skip?, note?, optional? }`
  - `ref`: `cp.*`(보편) 또는 `p.*`(직업 전용) · `step`: 해 나가는 순서(공통과 카테고리 항목을 합쳐 정렬)
  - `major: false` = 관련 학과 전공자는 건너뛴다(`skip` 에 이유). 계획은 **비전공자 기준으로 빈틈없이** 짜고 전공자용은 덜어 낸다
  - `optional`: 지원하는 곳에 따라 고르는 것
- 프로젝트의 `phases` = `[{ weeks, title, items }]`. 앱의 주차별 커리큘럼으로 옮길 때 weeks 만큼 펼친다
- `category`·`method` 는 앱 진로설계의 영역·진행 방식(`config/projectMethods.js`)과 같아야 한다

## 규칙
- 두 직업 이상에 겹치는 프로젝트는 직업 파일에 두지 말고 `common-projects.json` 으로 올린다(검사 스크립트가 같은 이름을 찾아 알려 준다)
- 실존 책·강의·학원 이름을 지어내지 않는다. 자격증은 실제 이름만 쓴다
- 고친 뒤 `node scripts/plan-library-validate.js --table` 로 검사한다
