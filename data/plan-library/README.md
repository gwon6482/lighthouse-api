# 진로계획 라이브러리 (plan-library)

직업별 **예시 진로설계**와, 여러 직업이 함께 쓰는 **보편 프로젝트**를 모아 두는 곳이다(2026-11-13 시작).
진로백과의 직업 537개를 계획 279개로 모두 덮었다 — 1차 우선순위 100개 + 2차 179개(2~4단계). 계획 하나가 비슷한 직업 여러 개를 함께 덮는다(`covers`).
진로 설계하는 사람이 빈 화면에서 시작하지 않게 하려는 자료이고, 쌓일수록 서비스의 재산이 된다.

> 지금은 **초안**이다. Claude 가 직업정보·공식 자격 목록·일반 지식으로 썼고, 채용공고 분석 근거는 아직 없다.
> "공고 몇 %가 요구" 같은 숫자는 쓰지 않았다. 시험 과목·응시자격·교육 시간처럼 바뀌기 쉬운 사실은 2026-11-13 에 법령·공고와 대조했다 — 결과와 고친 것은 `FACTCHECK.md`.
> 앱·DB 에는 아직 넣지 않았다(이 브랜치는 배포되지 않는다).

## 파일
| 파일 | 내용 |
|---|---|
| `taxonomy.json` | 분류 — 활동 유형 7가지(자격·학업·스킬·경험·산출물·채용 절차·네트워킹), 공통성 3단계(전 직무·계열·직무 특화), 계열, 계열별 묶음 |
| `common-projects.json` | 보편 프로젝트. id 는 `cp.<이름>` |
| `priority-jobs.json` | 계획 대상 279개 — 통칭, 계열, 세부 카테고리(tracks), 같은 계획을 함께 쓰는 직업(covers). 1차 100개는 `tier` 1~3, 2차는 `tier: null` 에 `wave`(2~4)·`batch` |
| `backlog.json` | 1차 뒤에 남은 직업의 작업 목록 — 단계(2~4)와 묶음(batch). 한 줄이 계획 하나(대표 직업 + 함께 덮는 직업). 만들 때 `adopt()` 로 `priority-jobs.json` 에 옮긴다. 2026-11-13 전부 `done` |
| `job-groups.json` | 추천 직무 112개와 1차에 넣은 직업, 뺀 이유 |
| `plans/<jobCode>.json` | 직업별 예시 진로설계 |
| `FACTCHECK.md` | 사실 확인 기록 — 대조한 출처, 고친 것, 아직 못 본 것, 다시 대조하는 방법 |
| `review/template.html` | 검토 페이지의 틀. `python3 scripts/plan-library-review.py <나올 파일.html>` 이 위 JSON 을 끼워 한 파일로 낸다(브라우저로 바로 열려면 `--standalone`). 나온 파일은 레포에 넣지 않는다 |

## 직업 계획의 구조
- `projects`: 그 직업만의 프로젝트(id 는 `p.<이름>`). 보편 프로젝트와 같은 모양이다
- `common`: 세부 카테고리와 상관없이 하는 것 / `byTrack.<id>`: 그 카테고리에서 더 하는 것
- 항목 = `{ ref, step, major, skip?, note?, optional? }`
  - `ref`: `cp.*`(보편) 또는 `p.*`(직업 전용) · `step`: 해 나가는 순서(공통과 카테고리 항목을 합쳐 정렬)
  - `major: false` = 관련 학과 전공자는 건너뛴다(`skip` 에 이유). 계획은 **비전공자 기준으로 빈틈없이** 짜고 전공자용은 덜어 낸다
  - `optional`: 지원하는 곳에 따라 고르는 것
- 프로젝트의 `phases` = `[{ weeks, title, items }]`. 앱의 주차별 커리큘럼으로 옮길 때 weeks 만큼 펼친다
- `category`·`method` 는 앱 진로설계의 영역·진행 방식(`config/projectMethods.js`)과 같아야 한다

## 확인 표시
보편 프로젝트·직업 계획·직업 전용 프로젝트에 붙는다. 한 항목에 여럿이 함께 붙을 수 있다.
- `checked: { at, level, source, note }` — 출처와 대조한 것. `level` 은 `law`(법령 조문·별표 원문) · `official`(기관 과목표·시행계획 공고) · `secondary`(보도·수험 안내 등 2차 자료)
- `caution` — 사실 확인 대상이 아니라 늘 붙어 있을 안내(공고마다 다르다, 계약 조건을 확인할 것 등)
- `verify` — 아직 원문을 보지 못한 사실. 새로 쓰는 계획에서 자신 없는 사실은 여기에 적고, 대조한 뒤 `checked` 로 옮긴다

## 규칙
- 두 직업 이상에 겹치는 프로젝트는 직업 파일에 두지 말고 `common-projects.json` 으로 올린다(검사 스크립트가 같은 이름을 찾아 알려 준다)
- 계열 공통 보편 프로젝트의 `families` 는 그것을 쓰는 계획의 계열을 모두 담는다(계열로 꺼내 쓰기 위해). 작성 도우미의 `save()` 가 채우고, 어긋나면 검사가 오류를 낸다
- 세부 카테고리를 나눴으면 카테고리마다 다른 항목이 하나는 있어야 한다. 예외는 '기본 경로' 하나(예: 공채 / 경력 채용에서 공채) — 나머지 카테고리가 거기에 더하는 꼴
- 실존 책·강의·학원 이름을 지어내지 않는다. 자격증은 실제 이름만 쓴다
- 고친 뒤 `node scripts/plan-library-validate.js --table` 로 검사한다
